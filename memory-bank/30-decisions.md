# 30 · 決策記錄

**呢頁最重要嘅係下半部：已經否決咗嘅方案。** 唔記低，就會有人再試一次。

## 採用咗

| # | 決策 | 理由 |
|---|---|---|
| D1 | Gemini 一個循環只叫一次，追蹤全本地 | 2~6 秒延遲，不可能逐格。網絡死咗幾何層照跑 |
| D2 | 暗箱當綠幕：色鍵去背 + 影像矩 | 固定相機 + 受控燈光 = 分割問題先天已解，唔使 ML |
| D3 | 由真實輪廓**推演一條唔同嘅** 2127 輪廓 | 貼身輪廓等於畫面上講「佢冇變過」，違反主旨 |
| D4 | 模組只存輪廓索引，唔存座標 | 每格重投影 → 跟住實體轉。存座標就會抖 |
| D5 | seed 用本機 `Date.now()`，唔問 Gemini 攞 | LLM 出嘅隨機數質素差；本機保證次次唔同 |
| D6 | 轉盤轉一圈 = 進度條，20 RPM | 一圈 3 秒 ≈ Gemini 中位延遲。物理節奏遮住網絡抖動 |
| D7 | 相機約 45°，**唔係正俯拍** | 正俯拍 + 垂直轉軸 = 純 2D 旋轉，面積恆定、形變量死掉、畫面好平 |
| D8 | 電動轉盤（非觀眾手轉） | 物體喺轉軸上 → 質心固定 → 錨點校正一次永久有效 |
| D9 | 一個 `<video>` 元素，全息化直接套 CSS filter | 四個元素指同一檔案會卡死載入（見 `40-gotchas.md`） |
| D10 | `clip-path: path()` + CSS filter，唔用 per-pixel JS | 720p 逐畫素 JS 只得 ~50fps；CSS 全 GPU |
| D11 | `#stage` 長寬比執行時對齊來源 + `object-fit:fill` | 追蹤空間到顯示空間只剩純縮放，消滅成類座標 bug |
| D12 | 進入節拍用 `onEnter()` 旗標 | `since() < 20` 呢種時間窗掉一格就永遠入唔到 |
| D13 | 連續 N 格偵測唔到先當物件拎走 | 影片 loop、手掃過、對焦都會掉單格 |
| D14 | Pepper's Ghost 係**同一個畫面嘅第二種輸出模式**（`?ghost=1`），唔係另一套渲染 | 現有配色本身就係暗底 + 自發光，改背景做純黑就已經合格。幾何層零改動 |
| D15 | 燈帶／音效／出卡全部綁死七節拍狀態機 | 另開一條時間軸 = 兩套嘢遲早唔同步。狀態機本身就係唯一真相 |
| D16 | 燈帶走 `POST /api/led`，前端唔直接掂硬體 | 同印表機同一條路（金鑰／裝置權限）。而且燈帶死咗展品唔可以死 —— 呼叫失敗吞掉 |
| D18 | 立體感靠**疊剖面 + 外殼帶 + 前後軌道環**，唔靠 WebGL | 全部係同一條已經算好嘅 2127 路徑再用一次（transform / fill / ellipse）。零新依賴，幾何層零改動 |
| D19 | 準星用四角括號，唔用整圈虛線 | 整圈 dashed lock-on 係 2012 年嘅 HUD 語言。括號讀落係儀器 |
| D20 | 虛空唔用透視地平網格 | 網格 = TRON 1982。改成深度環 + 光柱 + 三層視差塵埃，先至有縱深 |
| D21 | **轉盤降格做掃描器：捕捉環 + 自轉播放** | 顯示唔再追實體轉盤 → 相位／轉速同步問題根本唔存在（唔係「要控制」）。順帶：節奏可以做戲、REVEAL 唔再需要實體、輪廓噪聲消失 |
| D22 | 一圈幾多格（nominal）由**實測時間跨度**推；接縫比對要**明顯好過 nominal**（SSD < 0.6×）先算數 | 淨信相關性會畀你一個 2/3 圈嘅答案，一 loop 就跳。而且輕微噪聲會令每格都「差唔多似」，最細嗰個 k 純粹係噪聲揀出嚟 —— 籃球實測就係咁 |
| D24 | **實效格率 = `playRpm/60 × ringN` 係第一等公民**，寫咗檢查守住 ≥24fps | 第一版 48 格 × 12 RPM = 9.6fps，直頭係幻燈片。「順唔順」係格數預算，唔係轉速。上限係來源：`攝影機 fps × 一圈秒數` |
| D23 | 顯示統一走 `#disp` canvas，`#feed` 退做解碼來源 | live 同環共用一條顯示路徑 → clip-path／全息化／泛光唔使識分兩套。第 2、3 步（表面貼片、網格）都靠呢條路 |
| D25 | 模組錨喺**物體自身坐標 (θ, h)**，唔係射線索引 | 射線索引 = 固定畫面角度，籃球轉極剪影都係個圓 → 模組零位移 → 讀落係另一 layer。yaw 由環嘅格索引直接畀，唔使估 |
| D26 | 遮擋靠**圖層順序**（背面 → `#ovBack`），唔做遮擋計算 | `#ovBack` 喺影像下層，影像又被剪影 clip 住 → 「畀物體擋住」係免費嘅。深度測試／遮罩全部唔使寫 |
| D27 | `R(h)` 用**剪影喺嗰一行嘅半闊**，唔用 bbox 橢球 | 鎖匙嘅腰身同 bbox 差好遠，用橢球會令貼片浮離實體。圓柱體呢個就係真半徑；球體高估約 8%（貼片微凸，讀落似裝上去） |
| D28 | **真橫切面由捕捉環還原**（shape-from-silhouette），唔用橢球假設 | 一圈剪影本身已經係 360° 視角，白撿。每格喺某高度嘅左右外伸 = 該橫切面嘅支撐函數 → 半平面交集。交通卡先唔會被當成圓柱 |
| D29 | 轉軸 = **一圈質心平均**，唔用逐格質心 | 非對稱物體嘅剪影質心會繞住轉軸走。用逐格質心，貼片同網格會一齊擺。接縫收口令「一圈平均」有意義 |
| D30 | 表面網格緯線用 `--b` 粗、經線用 `--a` 幼，經線只畫正面 | 一色一粗幼會同掃描線撈埋變雜線。分色分粗幼先讀得出係網格；背面經線只會嘈 |
| D17 | 稀有度由幾何算（`morph` + 模組數），唔用亂數 | 同一件物品放兩次要差唔多，否則觀眾一試就知係假。而且稀有度只影響燈同卡框，唔影響文案 —— 誇大文案等於呃人 |

## 否決咗 —— **唔好再試**

| 方案 | 點解唔得 |
|---|---|
| **Three.js** | 所有元素（輪廓、HUD、準星、模組）都係螢幕空間 2D。加咗只換嚟座標換算 bug 同建置重量。**唯一合理理由係 bloom**（`UnrealBloomPass`），而且係第 5 日疊上去嘅附加層，唔係地基 |
| **影像生成（img2img / SDXL / 任何 diffusion）** | 5~15 秒延遲。物體仲喺實體轉盤度轉，貼一張靜態生成圖上去，同步即刻爆，AR 幻覺當場死 |
| **預製 3D 模型／kitbash greeble** | 唔知物體有幾深，對唔準，一睇就知硬 P 落去。而且冚唔到任意剪影 |
| **現成素材圖做「未來版本」** | 鑰匙同籃球嘅輪廓完全唔同，同一張圖套唔到 |
| **TF.js / MediaPipe / COCO-SSD 物件偵測** | 8MB 模型、得 80 類、框會抖。色鍵 + 影像矩 40 行做得更好更準 |
| **Marching Squares / Moore 邊界追蹤**（暫時） | 放射取樣夠用，仲**免費送法線**。展場物件夠緊緻。凹陷橋接係已知天花板 |
| **Web Serial 直駁印表機**（作為唯一方案） | 多數 USB 熱感應係 USB Printer Class（bulk），Web Serial 完全碰唔到。Node 常駐行程係永遠可行嘅退路 |
| **API 金鑰放前端** | 單檔 `index.html` 入面等於公開。Node 代理順手解決 |
| **密 CRT 掃描線做主要質感** | 2px 週期嘅橫紋係 1990 年代全息片語言。放疏到 4px、調淡到 .09，改由一條慢掃帶做主角 |
| **淨信接縫相關性、唔要 nominal 預設** | 旋轉對稱物（籃球）每格都似第 0 格，比對無意義；細長物又會喺半圈中招。試過就係 `RING 32/48`，播 2/3 圈然後跳 |
| **播一個實效格率唔夠嘅環** | 9.6fps 嘅「旋轉」比唔播仲差。`CFG.minFps` 以下直接退返 live |
| **用 `playRpm` 慢放做「電影感」** | 慢放 = 同樣格數攤長時間 = 更低 fps。想慢放就要先加插值（cross-fade），唔係扭個旋鈕 |
| **粒子群（THREE.Points 或 2D）** | 科幻 UI 嘅預設反射動作。已經有輪廓、節點、掃描線、模組，再加只會變嘈 |
| **考古學家 persona** | **違反核心主旨**，見 `00-intent.md`。Persona 係推演器 |
| **「遺物鑑定神社 / Artifact Appraisal Shrine」呢個名** | 同一個偏離嘅第二次現身（2026-09-05）。形式（懸浮箱／燈／音／卡）全部收，名字唔要。對外叫 **2127 進化神社 / Evolution Shrine** |
| **SSR / SR / R 稀有度標籤** | 抽卡黑話 + 「鑑定等級」味。用 `STANDARD` / `DIVERGENT` / `SINGULAR` |
| **`kept` 嗰下加音效** | 試過就知：留白先有力。嗰一刻**靜音 + 燈暗**，淨係得文字 |

## 睇得出但未做嘅選擇

- **實體卡片印表機**（vs 熱感應收據）—— 觀感差天共地，但耗材 10~60 円／張、
  每日 480 張、前置期未知。折衷：**預印卡 + 58mm 感熱貼紙**，硬體零改動。
  第 1 日同印表機驗證一齊決（見根 `README.md` §1.8.4）。

- **MONITOR 仲係浮空面板**，唔係真係貼喺表面 —— 因為佢有字要睇得清。
  而家只係根部釘死喺表面錨點、錨點轉到背面就淡出。要真上身就要處理可讀性（字會反轉、壓扁）。
- **`SLICES` 仲係假嘅** —— 九層都係同一條 2127 路徑縮放，唔係真橫切面。
  外殼已經有真 `R(h,θ)`，接得上，但要順住 `projectFuture` 嘅生長量一齊算，
  而 `projectFuture` 係主旨所在（D3）兼測試最密，未夠理由郁佢。
- **凹陷收唔返** —— 剪影法嘅天花板，而且 `radialContour` 本身已經橋接咗凹陷。
  要凹陷就要體素雕刻 + Moore 邊界追蹤，展場物件唔值。
- **ML 分割（`rembg-webgpu` / `@imgly/background-removal`）**—— 之前唔可能（要 60fps），
  而家只需要分割 48 格 ≈ 2.4 秒，塞得入捕捉之後。解透明／鏡面物體去背失敗。模型 40MB+ 要離線打包。
- **`surfaceStyle` enum**（`WIREFRAME` / `VOLUMETRIC` / `GLITCH` / `XRAY` / `CRYSTAL`）
  —— 設計咗但未入 schema。配合 `feTurbulence` 亂數 seed 可以令材質質感次次唔同。
