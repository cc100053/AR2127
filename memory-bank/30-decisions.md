## 2026-09-05 靜態造型測試（使用者最新授權）

先用使用者提供的手機相片驗證外觀，再加入旋轉。`phone.html` 獨立於原本影片路徑，復用零建置、零依賴的本地 Canvas 做法。第一版只換表面，使用者認為不夠有想像力。第二版保留下端握座與實體按鍵，移除上半矩形屏幕／機身，改為外露脊柱、三片相連感知翼及頂部感測器；用同一平面 homography 加校準高度顯示斜面、厚度及遮擋。原始影像在最終合成完全淡出，負空間必須真的透明。一次生成、靜態比較，不把同一張圖重複塞進捕捉環。

此版本是**人工校準的 2.5D 造型測試**，不是任意物件自動未來化。近白底去背只適合這張受控相片；更換相片需重新校準。1.8 秒是交叉淡化展示動畫時間（不是物理展翼模擬），並非 AI/API 生成延遲。歷史上全面否決影像生成／3D renderer 的理由不適用於所有靜態或離線播放方案；待造型和旋轉需求確立才決定，不在這次加入。

## 第二版方向已認可（使用者回饋）

認可的是創作原則：新增／移除實體結構、改變剪影、保留原物件可辨認的特徵、零件實際相連；不是把三片感知翼定為通用模板。目前仍是單張人工校準的 2.5D 程序概念，沒有通用生成或旋轉驗證。

建議先以兩種不同物件的靜態圖驗證上述原則，再建立結構化演化規格驅動渲染，接相機單張擷取，最後處理旋轉。**此順序僅是建議，尚未獲使用者授權執行。**

## 茶瓶／交通卡測試（最新里程碑）

使用者授權下一步並提供兩張相片。沿用「保留身份、新增／移除實體結構」原則，茶瓶選循環培養容器，交通卡選開口腕環，刻意不套用手機三翼造型。兩者放在 `studies.html` 共用控制與版面；不為三個手工概念抽象一套通用框架，手機已認可的渲染保持不變。

物件新增結構不必超出原照片邊界：腕環的中空、帶體厚度、相連識別面與開口都比外擴像素更有意義。測試依實際形態驗證；茶瓶檢查外部莢體，腕環檢查實心帶體／接合面與透明開口。兩者仍是人工校準、程序繪製，不聲稱自動重建或通用生成。

## 睇得出但未做嘅選擇

- **實體卡片印表機**（vs 熱感應收據）—— 觀感差天共地，但耗材 10~60 円／張、
  每日 480 張、前置期未知。折衷：**預印卡 + 58mm 感熱貼紙**，硬體零改動。
  同印表機實測一齊決（見 `../docs/exhibition-plan.md`）。

- **MONITOR 仲係浮空面板**，唔係真係貼喺表面 —— 因為佢有字要睇得清。
  而家只係根部釘死喺表面錨點、錨點轉到背面就淡出。要真上身就要處理可讀性（字會反轉、壓扁）。
- **`SLICES` 仲係假嘅** —— 九層都係同一條 2127 路徑縮放，唔係真橫切面。
  外殼已經有真 `R(h,θ)`，接得上，但要順住 `projectFuture` 嘅生長量一齊算，
  而 `projectFuture` 係主旨所在（D3）兼測試最密，未夠理由郁佢。
- **凹陷收唔返** —— 剪影法嘅天花板，而且 `radialContour` 本身已經橋接咗凹陷。
  要凹陷就要體素雕刻 + Moore 邊界追蹤，展場物件唔值。
- **ML 分割（`rembg-webgpu` / `@imgly/background-removal`）**—— 之前唔可能（要 60fps），
  而家只需要分割 48 格 ≈ 2.4 秒，塞得入捕捉之後。解透明／鏡面物體去背失敗。模型 40MB+ 要離線打包。
- **`surfaceStyle` enum**（`WIREFRAME` / `VOLUMETRIC` / `GLITCH` / `XRAY` / `CRYSTAL`）
  —— 設計咗但未入 schema。配合 `feTurbulence` 亂數 seed 可以令材質質感次次唔同。

## 同類物件唔等於同一個演化配方（2026-09-06）

使用者喺白色保溫鋼樽嗰陣提出：相同／相似物品係咪應該演化出同一個模樣。

**決定：唔係。配方要以「物件嘅功能同未解決嘅問題」為 key，唔係剪影分類。**

- `bottle-source.webp` 係即棄 PET 茶瓶 → 未解決嘅問題係「即棄」→ 演化成培養／過濾循環容器。
- `bottle-b-source.jpeg` 係真空保溫鋼樽 → 佢**已經解決咗即棄問題**。套茶瓶配方落去唔止色調錯
  （冇茶嘅樽出現茶色同「一口茶」文案），而係敘事上錯：等於將件嘢演化成佢本身已經係嘅嘢。
- 鋼樽嘅定義性質係「對抗環境、保住一個狀態」。推前一百年 →
  唔再靠人入水，改為自己由空氣抽水：真空夾層外露成冷凝鰭、底部進氣集水、側面集水柱。

同一張相片一定要推演出同一個結果（決定論，重播唔可以重擲）；同一個**類別**唔應該強制同一個配方。
呢個係以 `identity` / `function` 選配方嘅第一個實證。

同使用者討論後嘅暫定方案。**全部未有實物，冇一項經過實體驗證。**
呢度記低嘅係方向同理由，唔係已驗證嘅規格；具體數值（灰階反射率、背光亮度、

| # | 決策 | 理由 |
|---|---|---|
| H1 | **繼續 2.5D，唔用轉盤。** 攝影箱 + 正面一個鏡頭 | 靜態單張路徑已經走通兼獲使用者認可，係安全網。轉盤會將分割失敗模式乘以 N —— 由「1 張要成功」變成「36 張全部要成功」，而分割而家仲脆（麻布背景就 `kept=0.753` 全崩） |
| H2 | 目標**唔係 360°**，改為**正面 → 斜視嘅仰角轉場** | 真 360° 等於將 2D path 美術全部重寫成 3D 幾何，係重寫唔係擴展。仰角轉場玩中 2.5D 本身最強嗰點 |
| H3 | 第二個鏡頭放 **~45°，唔好 90° 頂視**（未起） | 高身物件由正上望落去只係一個細圓餅，修長剪影完全消失。45° 保住可辨認度，而且插值距離減半、假象容易撐住。**例外**：扁平物件（Suica、手機）先至係頂視最爆 |
