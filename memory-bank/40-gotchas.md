# 40 · 陷阱

每一條都真係燒過時間。撞到先睇，可以慳你幾個鐘。

## 環境

### `file://` 會令 canvas 跨來源污染
Chrome 當每個本機檔案係獨立來源，`getImageData()` 直接掟例外，追蹤即死。
**一定要用 HTTP 伺服器。** 頁面已經會顯示對應提示。
```bash
python3 -m http.server 8127
```

### yt-dlp 預設攞到 AV1，部分環境解唔開
症狀：`readyState` 一直 0、`networkState` 2、冇 error。
```bash
ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p -an demo.mp4
```

### 外殼會把薄物件當厚咗，誤差 ≈ `半闊 × tan(180°/n)`
`n=90` 個視角 = 方位角解析度 4°，所以一塊半闊 30、半厚 6 嘅薄片會被還原成半厚 7.05
（實測，`?test=1` 有守住）。**呢個係剪影法本身嘅極限，唔係 bug** —— 視角越多越準，
所以 `CFG.ringN` 同時服務播放順暢度同外殼準確度。

### 外殼假設轉軸係**垂直**嘅
橫切面係按「畫面上嘅水平行」量出嚟。物件打橫瞓喺台座上（例如鎖匙平放），
橫切面就會變成好闊嘅扁圓盤 —— 幾何上啱，但睇落怪。
展場擺法應該盡量令物件**企起身**，同 D7 嘅 45° 相機夾埋先靚。

### `CFG.spinDir` 一定要對住實物校
畫面轉向由環嘅播放次序決定，貼片轉向由 `θ + yaw` 決定 —— 兩者反方向就即刻穿崩
（物體向左轉、貼片向右行）。**冇得由 code 推出正確方向**，睇實體轉盤同相機擺法。
第 1 日裝好硬件就校：`?spin=-1` 試反轉，啱就寫入 `CFG.spinDir`。
`CFG.tilt`（預設 45）同樣要跟實際相機仰角。

### 貼片浮離表面 = `R(h)` 唔啱
`halfWidthAt()` 攞嘅係**剪影喺嗰一行嘅半闊**。圓柱體（鎖匙、唇膏）呢個就係真半徑；
球體會高估約 8%（貼片微微凸出，讀落似裝上去，可接受）。
用 bbox 橢球估就會差好遠 —— 試過，唔好返轉頭。要真半徑就要 shape-from-silhouette（第 3 步）。

### 播放順唔順係**格數預算**，唔係轉速
`實效格率 = CFG.playRpm/60 × CFG.ringN`。第一版 `48 × 12/60 = 9.6fps` —— 幻燈片。
改任何一邊都要重算，`?test=1` 有一條守住 ≥24fps。
上限係來源本身：`ringN ≤ 攝影機 fps × 一圈秒數`（30fps × 3s = 90）。
**想慢放就要加插值，唔係扭細 `playRpm`。**

`demo.mp4` 係 25fps／5 秒／125 格 → 一「圈」最多得 75 格唔同影像，
所以 HUD 通常顯示 84 左右而唔係 90。呢個唔係 bug。

### 捕捉環喺背景分頁會餓死
`ringPush()` 每格 rAF 最多收一格。rAF 被降到 1Hz → 一圈得三幾格。
`ringNominal()` 由**實測跨度**推，所以判斷唔會歪，但格數太少一樣冇得播 ——
`CFG.ringMinN`（12）以下自動退返 live，HUD 顯示 `RING n/cap LIVE`。
**Chrome 視窗一定要喺前面先驗得到播放。**

### `python3 -m http.server` 冇 Cache-Control，Chrome 會啟發式快取
改完 `index.html` 之後開 `http://localhost:8127/` 可能仲係舊版（`#disp` 唔存在、HUD 冇 `RING`）。
驗證嗰陣加個 cache-buster：`?v=2`。

### 背景分頁測唔到嘢
`document.hidden === true` → `requestAnimationFrame` 停、媒體唔載入。
症狀：`present` 凍結喺某個數、`readyState` 0。
**Chrome 視窗一定要喺前面**，否則改用 Node harness 做數值驗證。

## 已經修好嘅 bug（唔好復辟）

### 四個 `<video>` 指住同一個檔案 → 卡死
四個並發請求 + 四個解碼器。已收窄到**一個** video，
全息化直接對 `#feed` 套 CSS filter，色差用原生 SVG `feColorMatrix` + `feOffset`。

### `await play()` 會鎖死 boot
媒體載唔到時 `play()` 個 promise **可以永遠唔 settle**。
`playAll()` 而家唔 await，`boot()` 有 try/catch，而且**來源失敗都照跑 `loop()`**
（唔係嘅話成塊畫面死黑，睇落好似壞咗）。

### `#stage > *` 包山包海嘅 CSS
`inset:0; width:100%; height:100%` 連 HUD 面板都拉成全螢幕。
影像層而家要標 `class="layer"`，規則收窄成 `#stage > .layer`。

### SVG `viewBox` 會過期
啟動時設一次，之後 stage 尺寸一變，成組 SVG 座標就歪。**每格對齊。**

### 追蹤畫布長寬比同來源唔一致 —— **靜到冇聲嘅幾何 bug**
160×120（4:3）配 16:9 影片 → 物體被壓扁 → **圓球量出離心率 0.28 而唔係 0**，
細長物嘅主軸角系統性歪。`fitTracker()` 按來源設 `CFG.H`（而家 160×90）。
`?test=1` 有守住呢條。

### `mix-blend-mode: screen` 會洗白
全息化係**取代**，唔係疊亮。灰階副本 screen 上去會變一片白。

### 影片 loop 重頭會掉格 → 整個循環被打斷
單格偵測唔到就 reset 係錯嘅。要連續 `CFG.goneFrames` 格。
展場都需要呢個：手掃過、對焦一下都會掉格。

### `if (since() < 20)` 呢種時間窗守衛
掉一格就永遠入唔到，`reveal()` 完全唔會被呼叫。用 `onEnter()` 旗標。

## `c.rect()` 做 clip 冇 `beginPath()` —— 跨渲染累積（2026-09-06）

**症狀**：`flask()` 去過高仰角再返仰角 0，畫面同乾淨嘅仰角 0 差 102727 bytes，
差異集中喺樽頂條帶（x304–425, y130–198）。而且**第一次渲染先係啱**，之後全部被污染。

**成因**：canvas 嘅 current path **唔屬於 save/restore 狀態**。

```js
c.save();c.rect(0,0,728,96);c.clip();…;c.restore();   // ← 冇 beginPath()
```

`restore()` 還原唔到 path。所以每次渲染啲 rect 一路累積，`clip()` 攞到嘅係
**歷來所有 rect 嘅聯集**。更麻煩嘅係 rect 係喺**當時嘅 transform** 下入 path 嘅，
所以仰角 45°（`scale(1,k)`）留低嘅 rect 比仰角 0 嗰個大，下一次仰角 0 渲染
就會喺條帶外面畫多咗嘢。

**修法**：每個做 clip 用嘅 `c.rect()` 前面加 `c.beginPath()`。

**點解一直冇人發現**：`build()` 本身只跑一次，所以累積唔到。係加咗檔案輸入
（可重複載入）同仰角參數（同一次 session 內多次渲染）之後先浮出嚟。

**教訓**：`renderFuture()` 開頭嘅 `setTransform` + `clearRect` **保護唔到你** ——
`clearRect` 本身受現行 clip 限制，而 clip 正正就係被污染嗰樣嘢。

## 用「跟住漸變 flood」改良去背 —— 試過，實測有害（2026-09-08）

士多啤梨頂部嗰忽背景塊唔跟該行左右邊緣顏色，所以逐行背景模型清唔到佢。
睇落好明顯嘅修法：flood 除咗比對行模型，再容許**由上一粒像素行細步**
（局部容差），只要未偏離行模型太遠。

**實測四組參數，全部都食咗鋼樽。** 鋼樽下半截係光滑白鋼，同背景之間係連續漸變，
局部細步一路行得上去：

| 局部步 / 偏離上限 | 士多啤梨 kept | 鋼樽 base（原本 570） |
|---|---:|---:|
| tol×.4 / tol×2.5 | .506 → .376 | **455** |
| tol×.25 / tol×1.5 | .506 → .433 | **455** |
| tol×.15 / tol×1.5 | .506 → .446 | **548** |
| tol×.2 / tol×1.2 | .506 → .470 | **519** |

改善士多啤梨嘅每一個設定都同時剪短鋼樽 22–115 行。**呢個正正就係
「靜靜雞將已認可嘅美術縮放」嗰類回歸**（見上面茶瓶 base 嗰single）。已經 revert。

教訓：漸變背景同光滑物件喺局部像素層面係同一樣嘢，冇得靠局部規則分。
要改善呢類相，方向係人手修圖（`?lab=1`）或者影相時控制背景，唔係調 flood 參數。

## 位置式漸層喺部件範圍外會 clamp 成純色（2026-09-09）

**症狀**：使用者話水樽「似純粹用圓圈幾何工具畫出嚟」、材質低一個層次。
睇落似係幾何問題，其實**path 完全冇問題，係 fill 錯**。

**成因**：`grad()` 出嘅係**畫布座標**線性漸層。

```js
const pearl = grad(c, 280,0, 450,0, [...]);   // 只覆蓋 x 280→450
// pod A 喺 x 235–279，pod B 喺 x 459–510
shape(c, podA, pearl);   // 全部喺 ramp 之前 → clamp 成第一個 stop
shape(c, podB, pearl);   // 全部喺 ramp 之後 → clamp 成最後一個 stop
```

兩個圓柱體因此**一絲明暗都冇**，變成兩隻純色圓角矩形。
`flask()` 九個鰭、`bottle()` 兩個 pod 全部中招。呢個就係「vector clip art」觀感嘅來源。

**修法**：`metal(c, a0, a1, h, s)` —— 每個部件用**自己嘅範圍**開漸層。

**二次陷阱（修第一次嗰陣即刻撞到）**：
**彎曲部件連自己範圍都唔可以用。** 彎管嘅 path 會離開自己嘅直徑範圍，
一離開就 clamp。我試過 `pipe()` 用 `metal(c,244,264,…)` 去畫一條由 x=347
彎到 x=254 嘅管，結果**上半段彎位變全黑**（clamp 到 ramp 尾嗰個 12% 光度）。

曲面唔可以靠一個線性漸層表達橫切面。要用：

- **管** → 疊描邊：深色外殼 → 本體 → 圓芯 → 沿住**走向**（唔係橫切面）淡出嘅高光
- **彎帶** → 邊緣上色：主光側邊亮描、背光側邊深描、中間平色

**點樣一眼認出**：一個曲面部件睇落係**均勻單色**，或者一條管有一段**突然變死黑／死白**，
99% 就係 clamp，唔好去改 path。

**同類已知案例**：`cup()` 冇中招，因為佢一開始就係 `grad(c, cx-hw, 0, cx+hw, 0, …)`，
跟住部件半寬開。呢個先係啱嘅寫法。

### 舞台層同主體唔喺同一個 transform

**症狀**：輪廓光／燙金／顆粒睇落離開咗物件，或者大細唔啱。

**成因**：`rim`／`holo`／`grain` 係由 `future` 剪影生成，坐標同 `future` 一樣。
邊個 transform 之下畫佢哋，佢哋就跟邊個。`phone.html` 嘅 `draw()` 將主體縮 .84，
如果 `stageOverlay(ctx, mix)` 喺 `restore()` 之後先畫，就會用返原尺寸，即刻錯位。

**修法**：主體同 `stageOverlay()` 一定要喺同一個 `save()/restore()` 之內。
`stageBackdrop()` 相反 —— 佢係背景，要喺 transform 之外、卡面 clip 之內。

**一眼認出**：光暈同物件同形但唔同大細／偏位，而唔係亂咁一忽。
