## 新相片自動分割 + 第二個瓶類配方（2026-09-06）

- 新增 `assets/bottle-b-source.jpeg`（458×670，白色保溫鋼樽、灰藍漸層背景、有倒影）。
- **舊嘅 `min(rgb)>=233` 近白去背喺呢張相完全失效**：背景邊界中位數 min(rgb)=204、最大 221，
  全部低過門檻，所以一粒都清唔到（清除率 0.000 vs 舊相 0.739）。樽仲光過背景，
  調低門檻只會反過嚟食咗個樽。亮度規則喺呢個情況兩邊都唔work。
- 改成 `segment()`：**逐行背景參考**（該行左右邊緣顏色線性混合）→ Chebyshev 距離 ≤32 →
  邊界連通 flood → 逐行 span fill（直立樽每個高度水平凸，封住由倒影漏入中間嘅通道）→
  接觸陰影修剪。輸出錨點 `{top, base, cx, width}`，兩張相共用同一條路徑。

## 用網上相片驗證 segment() 穩定性（2026-09-06）

由 Wikimedia Commons 取五張 CC BY-SA 4.0 相片做測試（**冇 commit 入 repo**，避開
share-alike 傳染；URL 見下，要重跑可以自己抓）。

**發現：原本嗰個 sanity gate 純粹係幾何嘅（高度佔比 + 闊高比），完全偵測唔到分割失敗。**
五張入面三個負面樣本，兩個係**撞彩**靠比例超標擋到，另一張（麻布紋理背景嘅 Tiger 保溫樽）
背景一忽都冇清到、成塊布當咗前景，但比例啱啱好落喺範圍內，直接**放行**。

`kept`（未被清除嘅像素比例）本身就係直接訊號，而且分得好開：

| 樣本 | kept | 幾何 gate | 加 kept<.45 之後 | 應該 |
|---|---:|---|---|---|
| bottle-source（茶瓶） | 0.26 | PASS | PASS | PASS |
| bottle-b-source（鋼樽） | 0.16 | PASS | PASS | PASS |
| bourbon-white | 0.223 | PASS | PASS | PASS |
| evian-clear（透明膠樽） | 0.482 | **PASS** | FAIL | FAIL |
| niksun（戶外草地背景） | 0.600 | FAIL | FAIL | FAIL |
| steel-nocap（雜亂暗背景） | 0.718 | FAIL | FAIL | FAIL |
| tiger-tall（麻布紋理背景） | 0.753 | **PASS** | FAIL | FAIL |

已加 `s.kept<.45` 落 gate，同埋一項檢查 `background actually removed, not merely
plausible geometry`。加咗之後五張全部判斷正確。

**修正（同日稍後）：上面用 `kept<.45` 做門檻係錯嘅。** Evian 嗰張**分割其實成功咗**，
剪影乾淨；佢 kept 高只係因為個樽影得貼、佔畫面大。即係話面積門檻將「背景冇清到」同
「物件影得大」溝埋咗，會誤殺影得貼嘅相 —— 而觀眾拎嘢過嚟影，好大機會就係影得貼。

真正分得開嘅訊號係**剪影有冇同時掂到左右兩邊畫框**：分割成功嘅單一物件唔會，背景冇清到
嘅圖一定會。門檻改成 `!bothSides && kept<.6`，七張全部判斷正確，而且**透明樽而家係正確接受**。

| 樣本 | kept | 掂左右 | 判斷 |
|---|---:|---|---|
| 茶瓶 / 鋼樽 / bourbon | .26 / .15 / .22 | 冇 | 接受 |
| evian（透明） | .482 | 冇 | **接受**（分割成功） |
| niksun（戶外） | .600 | 左右都掂 | 擋 |
| steel（雜亂暗底） | .718 | 淨係左 | 擋（面積） |
| tiger（麻布） | .753 | 左右都掂 | 擋 |

**關鍵理解：透明本身唔一定會令分割失敗。** span fill 只需要**輪廓**生存，唔需要物件不透明；
Evian 靠招紙、坑紋同邊緣對比就夠。真正會死嘅係「冇招紙嘅純淨玻璃樽 + 平背景」，
輪廓對比塌晒，flood 由中間漏穿而 span fill 冇嘢可以錨。

另一個教訓：Wikimedia 頁面文字講嘅「plain background」**唔可信** —— 五張入面兩張標住
