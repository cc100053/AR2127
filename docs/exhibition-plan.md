# 實體展場計劃

呢頁只記錄**未落地或未經實物驗證**嘅展場工作。現行可運行功能見根目錄 [`README.md`](../README.md)，設計取捨及被否決方案見 [`memory-bank/30-decisions.md`](../memory-bank/30-decisions.md)。

## 目標體驗

- 場地：HAL 東京，「100 Years Later / 2127」
- 觀眾放入一件日常物品，系統展示原型同一百年後形態，再輸出可帶走嘅世代卡
- 目標單次循環：60 秒
- 冇網絡、去背失敗或硬件故障時仍要有清楚退路，唔可以整個展品死機

## 暫定擷取方案

- 攝影箱 + 正面固定鏡頭，維持 2.5D；唔用轉盤做現行主方案
- 背景用中灰、啞光、無縫弧面；白色同白／銀物件衝突，綠色會同物件身份及現有美術衝突
- 第二個約 45° 鏡頭已列入方向，但要等單鏡頭靜態流程完成後先做
- 兩視角中間幀只係近似轉場，唔可以宣稱係 3D 重建

以上理由、取捨同已擱置嘅轉盤方案見 [`memory-bank/30-decisions.md`](../memory-bank/30-decisions.md#擷取硬件方向2026-09-06暫定)。

## Gemini 語意層

Gemini 唔負責直接生成最終圖片，亦唔入逐格動畫迴圈。每次體驗只分析一次拍攝圖，加埋本地已量到嘅輪廓比例、主軸、色彩及去背信心，回傳受 schema 限制嘅設計參數：

- `identity`、`function`、`unresolvedNeed`：件物件係乜、解決乜、仲有乜未解決
- `keptParts`、`removedShell`：一百年後要保留同移除邊部分
- `recipe`、`modules[]`：選用邊種結構文法、加乜部件、裝喺物件邊個區域
- `material`、`palette`、`futureName`、`kept`：統一材質／色彩同展示敘事
- `confidence`：決定可唔可以用專屬配方

後端要驗證 enum、數值範圍、字數同位置；不合法欄位回退本地預設。API key 只放本地代理。送出前縮圖，拒絕人物／證件，亦唔轉錄相片文字。

概念回傳例（實作時按 renderer 現有能力收窄 enum）：

```json
{
  "identity": {
    "name": "真空保溫樽",
    "function": "保持液體狀態",
    "unresolvedNeed": "仍要由人補充水",
    "confidence": 0.91
  },
  "recipe": "ATMOSPHERIC_COLLECTOR",
  "keptParts": ["mouth", "base"],
  "removedShell": { "from": 0.22, "to": 0.78 },
  "modules": [
    { "type": "CONDENSER_FIN", "anchor": [0.5, 0.35], "scale": 0.8 },
    { "type": "WATER_COLUMN", "anchor": [0.72, 0.58], "scale": 0.6 }
  ],
  "material": "FROSTED_CERAMIC",
  "palette": "FROM_SOURCE",
  "futureName": "大氣採水容器",
  "kept": "仍然把一口水留在手中。"
}
```

## 未知物件策略

唔為每種可能出現嘅物件預畫完整 model。renderer 只維護少量可組合結構：外骨架、內核、鰭、支持臂、導管、接口；實際比例同位置由遮罩量度約束。

| 狀態 | 回應 |
|---|---|
| 高信心、已有功能配方 | 用專屬配方，再以量度值適配輸入輪廓 |
| 語意模糊或冇專屬配方 | 用通用剪影配方；Gemini 只影響材料、模組同故事 |
| 去背／幾何不可靠 | 唔生成似是而非結果；進入 Lab 修正或要求重拍 |
| Gemini timeout／離線 | 全本地通用配方繼續，使用罐頭文案 |

美術一致性由 renderer 守：至少保留一個辨認特徵、移除部分要真透明、新部件要有實際接點、尺寸跟物件、palette 由原相抽取。Gemini 揀意義，程式守幾何，避免自由生成造成漂浮零件或每次結果失控。

## Pepper's Ghost 輸出

參考：[Make an awesome 3D hologram projector using a plastic jar](https://www.youtube.com/watch?v=yFFSZliMN0c)。片中用手機黑底播放明亮魚影，再由透明容器反射，正面近距離觀看時似乎浮喺容器內。亦睇到透明膠邊、環境反光同觀看角度會削弱錯視。

展場版會沿用原理而唔照抄膠盒：輸出改成純黑底、高對比、左右鏡像；顯示器向透明板反射，外殼遮走螢幕同板邊。現場要實測透明板角度、雙重反射、亮度、可視範圍同觀眾高度。呢個係反射錯視，唔宣稱真正 3D hologram。

## 硬件決定前要驗證

| 項目 | 最小驗收 |
|---|---|
| 攝影箱 | 常見白、銀、深色、透明／反光物件各自拍攝；記錄去背成功率 |
| 相機 | 可固定對焦、曝光同白平衡；長時間運行唔漂移 |
| 第二鏡頭 | 高身同扁平物件都保留可辨認輪廓；兩視角可按遮罩錨點對齊 |
| 印表機 | 確認連接類型；實際印到日文點陣同 1-bit 輪廓 |
| 輸出耗材 | 以每日最多約 480 次循環估算紙量、成本、換紙同散熱 |
| 展示器材 | 現場亮度下測 Pepper's Ghost 可讀性、視角同對位 |

## 安全及營運紅線

- 觀眾可能放證件、訊息畫面或身體部位入去；任何將來加入嘅模型不得轉錄可見文字，亦要有拒絕人物／證件嘅路徑。
- API key 唔可以放前端；如加入雲端服務，要由本地代理處理並設硬性 timeout。
- 日文熱感應輸出應先喺 Canvas 畫成點陣，唔好假設印表機內置完整日文字庫。
- 最終驗收包含連續 50 次無人介入循環；一次成功唔等於可以展出。

## 下一個實體里程碑

先用一個受控背景、一類直立不透明容器完成：相機拍攝 → 去背／修正 → 既有配方 → reset。通過後先加入第二鏡頭或印刷，避免同時調試多條未驗證硬件路徑。
