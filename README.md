# 2127 形態推演 — 100 Years Later

即時 AR 展示裝置。觀眾把日常物品（鑰匙、交通卡、護唇膏）放上旋轉台座，
系統即時推演並疊加**這件物品一百年後的形態**，最後印出一張實體「2127 形態預測書」。

> **主旨（不要偏離）**：這是**向前推**，不是向後望。
> 呈現的是「你這件東西，一百年後會變成什麼樣」——
> 不是「2127 年的考古學家怎樣誤讀一件古代遺物」。
> 所有文案、視覺、狀態命名都必須是前向的：世代、演化路徑、保留了什麼、
> 而不是遺物、古代人、鑑定、歸檔。

- **展場**：HAL 東京 —— 主題「100 Years Later / 2127」
- **單次循環**：60 秒
- **形式**：Chrome kiosk（單機）+ 電動轉盤 + 熱感應印表機

# Part 1 — 規劃

## 1.1 核心設計決策

三個決定貫穿整份文件，其他所有東西都是它們的推論。

### 決策 A：Gemini 不在追蹤迴圈裡

Gemini 的往返是 2~6 秒，不可能做逐格追蹤。

- **Gemini 整場只跑一次** —— 負責命名、世界觀文案、主題分類（語意）
- **追蹤在本地端，每一格都做** —— 負責位置、輪廓、方位角（幾何）

兩者完全解耦。網路掛掉時幾何層照常運作，展品降級但不死。

### 決策 B：用物體自己的剪影，推演出一個**不一樣**的 2127 形態

不做影像生成的「未來版本」替換 —— 延遲會讓靜態生成圖與實體轉動脫節，AR 幻覺當場崩潰。

改為：由真實輪廓**程序推演**出第二條輪廓（`projectFuture()`）：
吸收細節（更流線）→ 在模組位置長出隆起 → 整體外擴一圈。

畫面上同時存在兩個形態：

- **2026 原型** —— 真實物體，形變後退成虛線
- **2127 形態** —— 較大、較流線、長了新結構的外殼，實線發光
- **對應連線** —— 兩者之間的放射線，直接畫出「這個變成這個」

`morph`（形變量）是真實可量的數：`mean(|r₂₁₂₇ − r₂₀₂₆|) / mean(r₂₀₂₆)`。

**對任何物體自動成立，零預製素材。**

### 決策 C：暗箱是一塊還沒用到的綠幕

固定相機 + 受控 LED + 封閉台座 = 影像分割問題先天已解。
台座鋪色鍵材質（綠色絨布或壓克力），色相去背即可拿到乾淨遮罩。
不需要機器學習函式庫、不下載模型、不需要 WebGL。

## 1.3 判斷分成三層

拆成三個獨立系統。任何一層失效，其他兩層照常運作。

| 層 | 執行位置 | 頻率 | 決定 | 失效時 |
|---|---|---|---|---|
| **語意** | Gemini 2.5 Flash | 單次 | 它現在是什麼 / 一百年後變成什麼 | 罐頭「推演失敗」世代卡 |
| **幾何** | 瀏覽器本地 | 每格 | 形狀、2127 輪廓、模組長在物體哪一面 | 置中固定尺寸準星 |
| **配色** | 硬編查表 | 單次 | palette / 粒子行為 / 字符組 | 預設 `UNKNOWN` 主題 |

**Gemini 決定意義，幾何決定形式，查表決定配色。**

> Persona 是**推演器**，不是考古學家。任何「2127 年的人誤讀了這件古物」的寫法都是
> 已經發生過兩次的偏離，見 `memory-bank/00-intent.md`。

### 幾何層自己會判斷形式

```
aspect = bbox 寬 / 高
complexity = perimeter² / area          （圓形 ≈ 12.6，越複雜越大）

細長（鑰匙、筆、護唇膏）  → 沿主軸的軸向能量束
圓胖（硬幣、瓶蓋）        → 同心環、反應爐處理
複雜（鑰匙圈、耳機）      → 高密度節點標記、電路感
```

形狀不同 → 視覺處理不同。觀眾會覺得系統「真的在看」。而且這一層完全不依賴 Gemini。

### `visualTheme` 必須是列舉

自由文字的主題 = 無法預測的算繪。六個固定值：

`CRYSTALLINE` ｜ `BIOMECH` ｜ `PLASMA` ｜ `ARCHIVE` ｜ `WEAPON` ｜ `UNKNOWN`

## 1.4 畫面編排：把「轉一圈」當成進度條

**一次完整旋轉 ≈ Gemini 的中位延遲。** 物理運動就是進度條 ——
觀眾看得懂，網路抖動永遠不會表現成一顆轉圈圈。

| 節拍 | 時長 | 畫面 | 觸發 |
|---|---|---|---|
| `IDLE` | — | 吸引迴圈、掃描網格 | `track()` 回 null |
| `DETECT` | 0.3s | 輪廓瞬間吸附成青色 | 遮罩面積穩定 |
| `PROJECT` | 1 圈 | 推演線由上而下掃過。**同時是捕捉環：轉盤在這裡降格成掃描器** | 送出 `/api/project` |
| `MORPH` | 1s | 環收口 → 畫面改播捕捉環（與實體脫鈎）。2127 外殼長出、表面網格亮起、模組 stagger 彈出 | Gemini 回應 |
| `REVEAL` | 10s | HUD 看板飛入，世代 / 形變量滾動。**物體可以拿走了，畫面照播** | — |
| `PRINT` | 4s | 出單 | 自動 |
| `RESET` | — | 淡出回 IDLE | 物體移走或 15s 閒置 |

Gemini 早回來 → 等這圈轉完。晚回來 → 多轉一圈。永遠對齊實體節奏。

## 1.5 硬體規格

| 項目 | 規格 | 備註 |
|---|---|---|
| 轉盤 | **20 RPM（3 秒 / 圈）** | 現場調校旋鈕：`RPM = 60 / 實測中位延遲` |
| 台座面 | 色鍵綠（絨布或壓克力） | 深色物體在黑台座上會去背失敗，所以用綠 |
| 背景 | 色鍵綠弧形背板（cyclorama） | 45° 視角會拍到物體後方，背景也要是綠的 |
| 相機角度 | **約 45°，不要正俯拍** | 正俯拍 + 垂直轉軸 = 剪影只是純 2D 旋轉，面積恆定、flux 讀數死掉、畫面很平 |
| 相機 | USB UVC，**手動對焦** | 固定微距下自動對焦會來回拉風箱 |
| 曝光 / 白平衡 | **必須鎖死** | 承重項目：任何漂移都會讓去背門檻走位 |
| 燈光 | LED 環燈，俯照 | 避免側光造成陰影被算進遮罩 |
| 印表機 | ESC/POS 58mm，**須確認為 CDC / 虛擬 COM** | 見 §1.6 風險 1 |
| 主機 | 任何能跑 Chrome 的機器 | Chrome kiosk 模式，`--use-fake-ui-for-media-stream` |
| 懸浮層 | 亞克力／PET 透明板，**45° 斜置**，上方朝下裝一片顯示器 | Pepper's Ghost。詳見 §1.8 |
| 台座燈帶 | WS2812B 可定址 LED，接 §1.8 的節拍事件 | 見 §1.8 燈光譜 |
| 音響 | 一對小型主動喇叭或指向性喇叭 | 展場很吵，低頻要夠 |
| 卡片印表機 | 見 §1.8「兩種輸出」——收據 or 卡片，**擇一，第 1 天決定** | 卡片機前置期比收據機長很多 |

物體在轉軸上 → **質心固定**。錨點校正一次永久有效，HUD 零抖動；輪廓照樣每格更新。
穩固錨點 + 活的外框，兩邊都拿到。

## 1.6 風險清單（依殺傷力排序）

### 1. Web Serial 很可能看不到印表機 ⚠️ 最高

多數 USB 熱感應印表機以 **USB Printer Class（bulk）** 列舉，Web Serial 完全碰不到。
只有暴露 CDC / 虛擬 COM Port 的機型可用。便宜的 58mm 中國製通常可以；
Epson TM-T20 / T88 通常不行。

→ **第 1 天就要買到並實測那一台**。永遠可行的退路：Node 常駐行程開著裝置，
對 localhost 開 `POST /api/print`。反正這個行程也要拿來代理 Gemini。

### 2. 日文會印成亂碼

58mm 印表機出廠字碼頁是片假名 / GB2312，**沒有漢字**。
任何日文輸出都必須用 `<canvas>` 算繪成點陣圖，走 `GS v 0`。
這跟 ESC/POS 純文字是不同的程式路徑。**現在就決定收據語言。**

### 3. 隱私 —— 最可能演變成真實事故

觀眾會把身分證、學生證、開著訊息的手機、自己的手放上打光台座，
而你會把模型讀到的內容**印在實體收據上**。

Prompt 必須明確：**絕不轉錄文件上的文字**、拒絕人物 / 身體部位、拒絕任何證件形狀物。
要有拒絕路徑與對應的畫面。

### 4. 自動曝光 / 白平衡漂移

在此架構下是承重結構，不是「最好有」。`applyConstraints` 設手動，或選有硬體鎖的攝影機。

### 5. 透明與鏡面物體去背失敗

玻璃、透明塑膠、手機螢幕。`area` 不穩定時退回置中固定準星 —— 與 Gemini 壞框共用同一條退路。

### 6. 紙張後勤

60 秒 × 8 小時 ≈ 每天 480 張。一卷 58mm 約 250 張短收據。
每天至少兩卷加備品。熱感應頭連續工作會過熱降速 —— 編列冷卻或第二台。

### 7. 離線 = 展品死亡

快取約 20 份預寫證書，對應通用分類。8 秒硬性逾時。

## 1.7 時程（7 天）

高風險、長前置的項目排在最前面。原始企劃把硬體放在第 5~6 天，那是反的。

> **前端已經跑完第 2、3、5 天的視覺工作**（假資料驅動，`?test=1` 67 項全綠）。
> 剩下的全部是硬體與後端 —— 見 `memory-bank/20-status.md` 的「未做」。

| 天 | 工作 | 完成標準 |
|---|---|---|
| **1** | 印表機：確認列舉方式，跑通一張收據（日文則走點陣圖）。Node 服務骨架。**同日決定收據 or 卡片（§1.8.4）。** | 手動觸發能印出一張 |
| **2** | 相機 → 色鍵去背 → `track()` → 質心 / bbox / 角度以純文字上畫面。**不做視覺。** | 數字跟著物體轉動變化 |
| **3** | 轉盤裝好並定速。**對著實物校 `CFG.spinDir` / `CFG.tilt`**（轉向反了會即刻穿崩）。確認捕捉環在真實攝影機下錄得滿（HUD 看 `RING n/cap fps`）。 | 貼片黏著實體轉，不是另一個 layer |
| **4** | Gemini 接上（兩格 0°/180°）。七節拍狀態機。退化保護。 | 端到端跑一次 |
| **5** | 音效素材（§1.8.3）、燈帶（§1.8.2）、稀有度（§1.8.5）、網格濃淡調校。**這是安全區，可吸收落後。** | 好看 |
| **6** | 實體箱體、打光、對焦 / 白平衡鎖定、輪廓線稿出單、紙張後勤。**Pepper's Ghost 斜板對齊校正（§1.8.1）—— 一定要留半天，算不準的。** | 實體完成 |
| **7** | 閒置迴圈、失效模式、**連續 50 次無人介入運轉測試**。 | 沒人顧也能活 |

第 7 天不是「最佳化」，是那個 50 次測試。
一個每四位觀眾就要有人來救的展品，即使功能全都會動，它依然是失敗的。

## 1.8 展示形式升級 —— 懸浮箱體、燈光、音效、卡片

> **命名紅線先講**：這一節的靈感來源用了「遺物鑑定神社」這個名字。
> **不採用那個名字。** 「遺物 / 鑑定 / Artifact / Appraisal」全部是向後望的詞，
> 直接違反主旨（見開頭與 `memory-bank/00-intent.md`）。
> 儀式感、神社感、抽卡感**全部保留**——只是儀式的內容是**推演未來**，不是鑑定過去。
>
> 對外名稱：**2127 進化神社 / Evolution Shrine**。
> 台座叫「推演台座」，不是「鑑定台」；輸出叫「世代卡」，不是「鑑定書」。

### 1.8.1 Pepper's Ghost 懸浮箱體

原本的做法是把 AR 疊加畫在螢幕上；升級是讓 2127 形態**真的浮在實體物件上方**。

```
        ┌─── 顯示器（面朝下）───┐
        │                      │
         \                    /
          \   45° 透明斜板   /       ← 亞克力／PET，觀眾看穿它
           \________________/
        ┌──────────────────────┐
        │   實體物件 + 轉盤      │      ← 觀眾放上來的東西
        └──────────────────────┘
```

- 渲染背景**必須是純黑 `#000000`**。黑 = 全透明，只有自發光的線條浮起來。
  現有配色（暗底 + 螢光輪廓）本來就吃這一套，**幾乎不用改**。
- 因此：`index.html` 要有 `?ghost=1` 模式 —— 背景強制純黑、隱藏所有非發光面板、
  **畫面上下鏡像**（斜板反射會左右／上下翻）。
- 對齊由物理決定：斜板角度、顯示器高度、物件高度。**留一組校正偏移旋鈕**
  （`?ghost=1&dx=..&dy=..&scale=..`），現場一定要調，算不準的。
- 亮度是承重項：環境光越亮，鬼影越淡。箱體內部要黑絨，開口要遮光罩。

**這不取代現有渲染，只是同一畫面的第二種輸出模式。** 幾何層一行都不用動。

> **排程**：`?ghost=1` **排在最後**。對齊完全由物理決定，沒有實體斜板就驗不了，
> 先寫只會寫出一組校不準的偏移值。

### 1.8.2 燈光：LED 燈帶跟著七節拍走

燈帶顏色直接綁狀態機（`10-architecture.md` 七節拍），不是另一套時間軸。

| 節拍 | 燈光 |
|---|---|
| IDLE | 青色，弱脈衝呼吸（~0.2Hz），吸引用 |
| 偵測到物件 | 一次快速白閃，然後轉穩定青 |
| 推演中（轉盤那一圈） | 順著轉盤方向的流水燈，速度 = 進度 |
| 形態浮現 | 主題色（`visualTheme` 查表）由中心往兩端擴散 |
| `kept` 那一句 | **暗下來**，只留一點主題色 —— 讓文字自己說話 |
| 出卡 | 主題色滿版 + 快閃三下 |

- 高稀有度（見 §1.8.4）時 **`kept` 之後補一次金色爆閃**，這是整場唯一的金色。
- 用 WLED 或 Node `:7127` 直推序列埠。前端 `POST /api/led {beat, theme, rarity}`。
  **前端不直接碰硬體**，跟印表機同一條路。
- 燈帶掛了展品不能死：`/api/led` 失敗吞掉，只 log。

### 1.8.3 音效

WebAudio 已經在跑（現有 A/B/C/D 視覺層的一部分），這裡只是把素材補齊：

| 時機 | 聲音 |
|---|---|
| 推演開始 | 低頻轟鳴 + 上升的能量充填（3 秒，對齊轉盤一圈） |
| 形態浮現 | 一下爆發（能量釋放），然後留殘響 |
| 模組長出來 | 每個模組一聲短促的機械 click，錯開 ~80ms |
| `kept` | **靜音**。留白比任何音效有力 |
| 出卡 | 氣動洩壓「嘶」聲 + 電子嗶 |

- 素材全部預載成 `AudioBuffer`，**不要在節拍當下才 `fetch`**。
- 展場很吵：低頻要夠，高頻細節聽不到，不要花時間在上面。
- 靜音開關 `?mute=1`（給調試與深夜留守用）。

### 1.8.4 輸出：卡片 vs 收據

原案想要 **Pokémon 風實體閃卡**。這比熱感應收據好看非常多，但是另一種硬體。

| | 熱感應收據（現行計畫） | 實體卡片（升級） |
|---|---|---|
| 硬體 | 58mm ESC/POS，便宜、確定買得到 | 卡片印表機或預印卡 + 熱昇華，貴、前置期長 |
| 單張成本 | ~0.3 円 | 卡片機耗材 10~60 円／張 |
| 每天 480 張 | 兩卷紙搞定 | **成本與補卡都是真問題** |
| 觀感 | 「拿到一張紙」 | 「拿到一張卡」——留存率天差地遠 |
| 前置風險 | 已知（§1.6 風險 1） | 未知，要重跑一次驗證 |

**決定點在第 1 天**，跟印表機驗證同一天，不要拖。

折衷方案（推薦，也最懶）：**預印卡 + 熱感應貼紙**。
卡片正面是統一的 2127 進化神社版面，預先大量印好；
現場只印一張 58mm 感熱貼紙（輪廓線稿 + 世代 + `kept`），貼上卡片凹槽。
硬體完全不用改，觀眾拿到的還是一張卡。

### 1.8.5 稀有度

抽卡感需要稀有度，但**稀有度必須從幾何來，不能亂數**，否則就是假的。

現成可用的量：`morph`（形變量）、`ecc`（離心率）、模組數、`area` 穩定度。

```
rarity = f(morph, moduleCount)     // 例：morph 大 + 模組多 = 高稀有
```

- 分級沿用前向詞彙：`GEN-07 / STANDARD` → `DIVERGENT` → `SINGULAR`。
  **不要用 SSR / SR / R** 這種抽卡黑話，也不要用 S 級「鑑定」等級。
- 高稀有度只影響**燈光 + 卡面框線 + 一次金閃**，不影響文案內容。
  觀眾的物件不會因為稀有度而被講得比較誇張 —— 那會變成在騙人。
- 稀有度要**可重現**：同一件物品放兩次應該差不多。所以用幾何，不用 `Date.now()` seed。

## 2.2 追蹤核心

```js
// 色鍵去背 → 質心 / bbox / 主軸角。160×H，每格約 0.5ms。
// ⚠ H 必須由來源長寬比算出（fitTracker），寫死 120 會把 16:9 影片壓扁 ——
//   圓球會量出離心率 0.28、細長物主軸角系統性歪。這個 bug 靜到沒有聲音。
const W = 160, H = Math.round(W * video.videoHeight / video.videoWidth);   // 目前 160×90
const c = new OffscreenCanvas(W, H), x = c.getContext('2d', { willReadFrequently: true });

function track(video, keyHue = 120, tol = 42) {          // 台座色相：綠色約 120°
  x.drawImage(video, 0, 0, W, H);
  const d = x.getImageData(0, 0, W, H).data;
  const mask = new Uint8Array(W * H);
  let m00 = 0, m10 = 0, m01 = 0, m20 = 0, m02 = 0, m11 = 0;
  let x0 = W, y0 = H, x1 = 0, y1 = 0;

  for (let i = 0, p = 0; p < d.length; p += 4, i++) {
    if (hueDist(d[p], d[p+1], d[p+2], keyHue) < tol) continue;   // 是台座 → 背景
    const px = i % W, py = (i / W) | 0;
    mask[i] = 1;
    m00++; m10 += px; m01 += py; m20 += px*px; m02 += py*py; m11 += px*py;
    if (px < x0) x0 = px; if (px > x1) x1 = px;
    if (py < y0) y0 = py; if (py > y1) y1 = py;
  }
  if (m00 < 50) return null;                                     // 台座上沒東西

  const cx = m10/m00, cy = m01/m00;
  const a = m20/m00 - cx*cx, b = m11/m00 - cx*cy, cc = m02/m00 - cy*cy;
  const ecc = (a+cc) > 0 ? Math.hypot(a-cc, 2*b)/(a+cc) : 0;
  return {
    cx, cy, bbox: [x0, y0, x1, y1],           // **追蹤空間**，不正規化
    ecc,                                       // 0 = 完美圓形（籃球！）
    angle: ecc < 0.10 ? null                   // 圓形物體沒有主軸 —— 給 null，別讓 atan2 噴雜訊
                      : 0.5 * Math.atan2(2*b, a - cc),
    area: m00 / (W*H),
    mask,
  };
}
```

> `#stage` 的長寬比執行時對齊來源、`object-fit: fill` → 追蹤空間到顯示空間**只剩純縮放**，
> 沒有 letterbox 位移。這個設計消滅了整整一類座標 bug。

**平滑不要做過頭。** USB 攝影機本身已有 60~120ms 端到端延遲。
只用輕度 EMA（α ≈ 0.5）。**延遲讀起來像「壞掉」，輕微抖動讀起來像「正在掃描」。**
寧可偏向抖動。

## 2.3 捕捉環、顯示路徑、變身

### 轉盤是掃描器，不是即時追蹤的對象

畫面**不需要**跟著實體轉盤轉。`PROJECT` 那一圈把影像錄進一張 sprite sheet、
逐格存下輪廓，`MORPH` 收口之後畫面改播這個環，速度由 `CFG.playRpm` 決定。

**所以我們永遠不需要知道真實 RPM，只需要知道格的次序。** 轉盤快了慢了、皮帶鬆了，
播出來只是速度輕微不均，肉眼零感覺 —— 相位／轉速同步問題不是「要控制」，是根本不存在。

```
實效格率 = playRpm/60 × ringN          ← 播出來順不順就是這個數
上限     = 攝影機 fps × 一圈秒數        ← 30fps × 3s = 90
```

第一版用 `48 × 12/60 = 9.6fps`，是幻燈片。`?test=1` 現在有一條硬檢查守住 ≥24fps。

接縫（一圈到底幾多格）**不靠計時，靠半徑指紋比對**，而且是
「nominal 做預設、比對明顯更好才修正」—— 純信相關性會給你一個 2/3 圈的答案，一 loop 就跳。

### 一條路徑，三個用途

```js
const d = toPath(smooth, sx, sy);              // 放射取樣 64 點 → "M12,4 L18,9 ..."

disp.style.clipPath = `path('${d}')`;          // ① 影像被裁成物體形狀，綠幕消失
edge.setAttribute('d', d);                     // ② 同一條線 → 發光外框
latRing.style.clipPath = `path('${d}')`;       // ③ 表面網格只畫在物體身上
```

`#disp` 是唯一的顯示畫布：live 影格和捕捉環都畫進它，
所以 clip-path／全息化／泛光**不用分兩套**。`<video>` 退居成純解碼來源。

> 用的是**放射取樣**，不是 Marching Squares。放射取樣免費送一份大禮：
> 第 i 點的法線就是第 i 條射線方向。代價是凹陷會被橋接（帶孔的鑰匙圈畫不出孔），
> 展場物件夠緊緻，先不用升級。

### 從同一條輪廓再長出來的（全部免費）

- **外擴光場** —— 同一路徑畫三次，`stroke-width` 遞增、`opacity` 遞減
- **節點標記** —— 輪廓上等距取 12 點，各掛小括號 / 十字 / 編號，物體看起來「被儀器化」
- **體積投影** —— 輪廓複製數份，逐份上移數像素、透明度遞減 → 假立體光柱
- **能量通量** —— `d(area)/dt`。轉到側面時面積驟縮，數字跟著跳

因為輪廓每格重算，這些全部**跟著實體一起轉**。

## 2.4 2127 改造模組

物體嘅「變身」唔係換走佢，係用佢自己嘅剪影做生成素材。
零件**存嘅係物體自身坐標 `(方位角 θ, 高度 h)`**，唔係畫面座標、亦唔係輪廓索引。

```
θ' = θ + yaw          yaw = 捕捉環嘅格索引，唔係估出嚟
x  = axisX + R(h,θ)·sin θ'
y  = yBase + R(h,θ)·cos θ'·sin(tilt)     tilt = 相機仰角，CFG.tilt
z  = cos θ'                              >0 面向觀眾，<0 喺背面
橫向壓扁 = |z|                            轉到邊緣就得返一條豎線
```

因為影像同貼片共用同一個格索引，兩者係**數學上鎖實**，唔係「睇落似」。

- `R(h,θ)` 由 `buildHull()` 出 —— 一圈剪影 → shape-from-silhouette → 真實半徑。
  交通卡唔會被當成圓柱。冇環（LIVE 退路）先退返「剪影半闊」嘅旋轉體假設。
- **轉軸 ≠ 質心。** 非對稱物體嘅剪影質心會繞住轉軸走，用逐格質心貼片會一齊擺；
  轉軸取一圈平均（接縫收口令呢個平均有意義）。
- **遮擋免費。** `z<0` 嘅零件搬去 `#ovBack`（喺影像層下面，而影像被剪影 clip 住）
  → 唔使寫任何遮擋計算。

```
Gemini modules  →  邊幾種零件（語意）
seed            →  幾多顆 / 擺邊 / 幾大（排列，mulberry32）
visualTheme     →  顏色（配色）
物體半徑        →  整體縮放（絕對像素喺大物件上會細到睇唔見）
```

同一條鎖匙，`seed = Date.now()` 每次唔同 → 永遠唔會出到一樣嘅佈局。

| 零件 | 掛喺邊 | 狀態 |
|---|---|---|
| `CHIP` | **貼喺物體表面**，跟住轉、到邊緣壓扁、繞去背面被擋住 | ✅ |
| `MONITOR` | 根部釘死喺表面錨點，面板保持浮空（要睇得清字），錨點轉到背面就淡出 | ✅ |
| `CONDUIT` | 兩個表面錨點之間，CSS `stroke-dashoffset` 做流光 | ✅ |
| `HEATSINK` / `PORT` / `ANTENNA` / `CORE` / `VENT` | — | 未做，暫時當 CHIP |

`at:[x,y]` 嘅語意：**物體中心 = 面向觀眾（θ=0）**，左右邊緣 = ±90°，上下只改高度。

### 表面網格

緯線（真橫切面，`--b` 粗）+ 正面經線（`--a` 幼），兩條都剪落剪影度。
呢個係「物體本身變咗」嘅實證 —— 之前所有嘢都住喺物體外面。

## 2.5 API 契約

```jsonc
// POST /api/project   body: { frames: [<b64 @0°>, <b64 @180°>] }
// Prompt 方向：「這是 2020 年代的物品。向前推一百年 —— 它變成什麼？
//               什麼被取代、什麼消失、什麼一直沒變？」
// temperature 開 1.1~1.3 —— 預設太保守，同一件物品會次次出差不多的文案
// 最長邊 1024px，JPEG q0.8。不要送 1080p。
{
  "now":         "黃銅家門鑰匙",              // 現在是什麼
  "futureName":  "持有權密鑰",                // 2127 年它叫什麼
  "gen":         7,                          // 第幾代
  "form":        "生體共生型",                // 形態類別
  "lineage":     "2038 無線化 → 2064 生體綁定 → 2099 量子簽章",
  "kept":        "仍然要握在手裡，仍然會弄丟。",  // ★ 整件事的情感落點，≤20 字
  "visualTheme": "ARCHIVE",                  // enum，見 §1.3
  "modules": [                               // 3~5 個，決定長出什麼結構、長在哪
    { "type":"CHIP",    "at":[790,470], "label":"密鑰陣列" },   // 齒紋端
    { "type":"PORT",    "at":[250,500] },                      // 握把端
    { "type":"CONDUIT", "at":[520,430] },
    { "type":"MONITOR", "at":[300,760], "label":"持有權" }
  ]
}
```

**`at` 是位置提示**：`[x, y]`，正規化 0–1000，**第一格影像空間**（注意是 x 先，
不是 Gemini bounding box 慣用的 y 先）。系統把它換算成「由物體質心出發的射線角度」，
再吸附到最近的輪廓索引。

這一欄讓變形變得**語意化**而不是亂數：鑰匙的齒紋端長出密鑰模組、握把端長出握感層。
`projectFuture()` 的隆起也長在同一批位置，所以 2127 形態的輪廓會在對的地方鼓出來。

| 行為 | 說明 |
|---|---|
| 沒給 `at` | 退回亂數擺位，一切照常 |
| 兩個模組 `at` 太近 | 沿輪廓向兩邊推開，不會亂飛到另一側 |
| `label`（≤6 字） | 顯示在 MONITOR 螢幕上，取代亂數的 `FLUX·47` |
| `type` 未實作 | 退回 `CHIP`（目前只有 CHIP / MONITOR / CONDUIT） |
| `CONDUIT` | 自動接回前一個實體模組，讀起來是「模組之間的接線」 |

> **Prompt 要寫清楚**：`at` 是那個模組**裝在物體的哪個部位**，不是它在畫面上的
> 裝飾位置。問法：「這個模組長在物體的哪裡？為什麼是那裡？」

> **天花板**：`at` 只在掃描那一格有效。之後物體轉動，模組留在同一個角度
> （見 `memory-bank/30-decisions.md`）。

> `kept` 是最重要的一欄。「一百年後仍然沒變的那件事」才是讓人拍照的那句 ——
> 規格再炫都只是包裝。

**注意**：`boundingBox` 已從契約中移除 —— 幾何層每格自己算，比 Gemini 準且免費。

## 已知取捨

| 取捨 | 天花板 | 何時升級 |
|---|---|---|
| 色鍵去背而非 ML 分割 | 透明 / 鏡面物體失敗 | 失敗率 >10% 時換 MediaPipe Selfie-Seg |
| 逐格 CSS clip-path | 極複雜輪廓時路徑字串偏大 | 超過 ~500 點就先做 Douglas–Peucker 簡化 |
| 圓形物體（球、硬幣）無主軸 | `ecc < 0.10` 時主軸給 null，顯示 RADIAL SYM | 需要球的轉動就得改追紋理，不是剪影 |
| 外殼把薄物件當厚了 | 誤差 ≈ `半闊 × tan(180°/n)`；90 個視角 → 半厚 6 還原成 7.05 | 提高 `CFG.ringN`（同時改善播放順暢度） |
| 外殼假設轉軸垂直 | 物件打橫躺著時橫切面變成很闊的扁圓盤 | 展場擺法讓物件立起來 |
| 凹陷收不回來 | 剪影法定律；`radialContour` 本身也已橋接 | 體素雕刻 + Moore 邊界追蹤，展場物件不值 |
| `SLICES` 九層仍是同一條 2127 路徑縮放 | 不是真橫切面 | 外殼已接得上，但要順著 `projectFuture` 的生長量一起算 |
| `MONITOR` 仍是浮空面板 | 不是真的貼在表面 | 放棄細字、改用圖形讀數才做得到 |
| `CFG.spinDir` / `CFG.tilt` 靠人手校 | 轉向反了會即刻穿崩 | 第 1 天裝好硬件對著實物校，`?spin=-1` |
| 無 WebGL | 光暈偏平 | 展場投影機看起來不夠亮時加 UnrealBloomPass |
| Gemini 單次呼叫 | 物體換了不會重新辨識 | 面積變化 >40% 時重掃 |
